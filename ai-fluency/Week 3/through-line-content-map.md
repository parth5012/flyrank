## 3. Laddering Breakdown by Page

| Page / Section | What it says | How it ladders to the One Action |
|---|---|---|
| **`/` (Hero)** | States the claim, proof paragraph, 3 verified metrics (8 eval cases, 60 records, 6 prompt versions). | Establishes immediate differentiation from generic "AI Engineer" portfolios; primary CTA buttons point straight to `/contact` and `/projects`. |
| **`/` (Method Strip)** | 01 Evaluate, 02 Isolate Failure, 03 Price It. | Shows the visitor *how* reliability is achieved before asking them to trust it. |
| **`/projects` (Work Archive)** | Five real cases with 3 beats: Problem, Built, Learned. | Provides verifiable GitHub evidence, run reports, and code snippets rather than mockups. |
| **`/projects/<slug>` (Detail)** | Deep dive into each system's failure modes, metrics, and honest limitations. | Eliminates skepticism: shows that edge cases and failures were anticipated. Closes with a CTA block to pilot. |
| **`/reliability` (Where It Breaks)** | Public audit of 6 real weaknesses (classifier urgency unscored, scraper selector coupling, in-memory rate limiting). | The ultimate trust builder: proving that we know our limits and do not hide defects. |
| **`/about` (Personnel File)** | Background in CSE (AI & DS), OSS contributions (SWOC, ECWoC), philosophy on unglamorous engineering. | Humanizes the builder as someone dedicated to measurable systems over hype. |
| **`/blog` (Story)** | Honest build-in-public account: AI built the code, but the contact form initially lied until attacked. | Reinforces the mindset: automated tools need rigorous human testing. |
| **`/contact` (The Action)** | Clean input fields, real-time server validation, honeypot protection, rate limiting, and an explainer of the data flow. | **The destination.** Converts a convinced founder into an active conversation without friction or false promises. |
